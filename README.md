# Исследование трансформеров для оценки грамматической приемлемости текстов на русском языке

Проект представляет собой комплексное исследование и сравнительный анализ различных архитектур трансформеров (encoder-based RuBERT, causal language model RuGPT3 в режиме few-/zero-shot, и sequence-to-sequence модель RuT5/mt5-small) на задачу определения грамматической приемлемости предложений в русском языке (датасет RuCoLA).

## 📊 Обзор проекта и датасет

Задача оценки грамматической приемлемости (Linguistic Acceptability) заключается в определении того, является ли предложение корректным с точки зрения синтаксиса, морфологии и лексики русского языка. 

В исследовании используется датасет RuCoLA (Russian Corpus of Linguistic Acceptability):
- **Train (обучающая выборка):** 7,869 предложений (после стратифицированного разделения: 6,295 train / 1,574 validation).
- **Dev / Test (тестовая выборка):** 983 предложения.
- **Метки классов (`acceptable`):** бинарная классификация (1 — грамматически приемлемо, 0 — неприемлемо).
- **Длина предложений:** максимальная длина в токенах составляет 225 токенов.
- **Баланс классов:** преобладают грамматически корректные предложения (~74.5% класс 1, ~25.5% класс 0), что требует аккуратной интерпретации метрики Accuracy и внимания к метрикам по классам (Precision, Recall, F1-score).

---

## ⚙️ Архитектура исследования и методы

В тетрадке `transformers.ipynb` реализовано 4 основных этапа:
1. **Базовый классификатор (Dummy Classifiers):** Оценка константного и случайного предсказателя для установления нижней границы качества.
2. **Тонкая настройка RuBERT (`DeepPavlov/rubert-base-cased`):** Классификация последовательностей с максимальной длиной входа 225 токенов, дообучение с использованием `Trainer`, `EarlyStoppingCallback` и стратифицированного кросс-валидационного разбиения.
3. **Few-/Zero-shot оценка RuGPT3 (`sberbank-ai/rugpt3large_based_on_gpt2`):** Тестирование генеративной модели без дообучения с использованием 3 различных шаблонов промптов и разным числом примеров в контексте (0-shot, 1-shot, 2-shot, 4-shot) путем оценки лоджитов для слов «да» / «нет».
4. **Тонкая настройка RuT5 (`google/mt5-small`):** Подход Seq2Seq, где входное предложение подается кодировщику, а декодер генерирует текстовый ответ («да» или «нет»). Использовались взвешенный сэмплинг классов (`WeightedRandomSampler`) и градиентная аккумуляция.

## 🏆 Результаты экспериментов и точность моделей

| Модель | Стратегия / Конфигурация | Accuracy (Точность) | Описание / Особенности |
| :--- | :--- | :---: | :--- |
| **Dummy (constant)** | Предсказание мажоритарного класса | 0.7457 | Базовый уровень за счет дисбаланса классов |
| **Dummy (random)** | Равномерно случайное предсказание | 0.4934 | Нижняя граница случайного угадывания |
| **RuBERT** | Fine-tuning (10 эпох, lr=2e-5, bs=32) | **0.7762** | **Лучший результат** среди всех подходов |
| **RuGPT3** | 4-shot (Prompt 2: лингвистический контекст) | 0.7467 | Сильный zero-/few-shot результат без обучения |
| **RuT5 (mt5-small)** | Seq2Seq Fine-tuning (5 эпох, lr=1e-4) | 0.7091 | Генеративный подход с генерацией токенов «да/нет» |

## 📈 Интерпретация графиков и измерений времени

1. **Динамика RuGPT3 Few-Shot (График точности от числа примеров):**
   - Эксперименты показали, что добавление few-shot примеров (с 0 до 4) в целом стабилизирует и повышает точность модели (особенно для промпта №1, выросшего с 0.586 до 0.744). 
   - Выбор формулировки промпта (prompt engineering) играет критическую роль для генеративных языковых моделей: промпт с ролевой инструкцией («Ты лингвист...») показывает высокую базовую точность на 0-shot (0.7467), но хуже реагирует на добавление примеров из-за ограничения длины контекста и специфики токенизации.

2. **Обучение RuT5 (Графики Loss и Validation Accuracy):**
   - Функция потерь (Training Loss) стабильно снижается от высоких значений до ~0.39. Точность на валидации достигает пика 0.7027 на 3-й эпохе, после чего наблюдается стабилизация или легкое плато, что свидетельствует об исчерпании емкости компактной модели `mt5-small` в условиях жестких ограничений.

3. **Замеры времени выполнения:**
   | Этап исследования | Время выполнения |
   | :--- | :---: |
   | Токенизация датасетов | ~2.3 сек |
   | Обучение RuBERT | ~1,750 сек (~29 мин) |
   | Инференс RuBERT | ~12.6 сек |
   | Инференс RuGPT3 (все промпты и шоты) | ~767 сек (~12.8 мин) |
   | Обучение RuT5 (mt5-small) | ~4,336 сек (~72.2 мин) |
   | Инференс RuT5 | ~26.0 сек |

## 🔬 Влияние аппаратных ограничений и гиперпараметров

В ходе выполнения работы были учтены жесткие ограничения вычислительных ресурсов (доступная VRAM GPU и ограничения по времени выполнения):
- **Минимальные гиперпараметры:** Чтобы нейросети обучались в разумные сроки без перегрузки памяти, размер батча (batch size) был снижен, количество эпох ограничено (10 для BERT, 5 для T5), а для RuGPT3 тестирование проводилось на подмножестве датасета (`dev_df`) с ограничением до 4 few-shot примеров.
- **Выбор архитектур:** Использование легковесных моделей (`DeepPavlov/rubert-base-cased` и `google/mt5-small`) позволило завершить циклы обучения на доступном железе.
- **Влияние на результаты:** Ограниченная емкость и короткое обучение привели к тому, что модели не полностью раскрыли свой потенциал (например, у RuBERT полнота по минорному классу `unacceptable` составляет 0.39, модель склонна чаще предсказывать мажоритарный класс `acceptable`). Тем не менее, качество дообученного RuBERT превосходит базовые уровни и few-shot аналоги.

## 🎯 Общие выводы

1. **Эффективность специализированных энкодеров:** Для задач классификации текста (таких как оценка грамматической приемлемости RuCoLA) классические encoder-based модели (RuBERT) демонстрируют наилучшее соотношение качества (Accuracy 0.7762) и затрат ресурсов.
2. **Возможности In-Context Learning:** Без какого-либо дообучения большая языковая модель RuGPT3 способна решать задачу классификации на уровне специализированных моделей при условии правильного подбора промпта и добавления нескольких примеров (few-shot).
3. **Особенности Seq2Seq подхода:** Подход с генерацией ответа («да» / «нет») с помощью RuT5 (`mt5-small`) работает корректно, однако уступает энкодерам в задачах классификации при ограниченном бюджете обучения из-за сложности процесса генерации текста и меньшей адаптации архитектуры T5 к чисто дискретным задачам классификации.

## 📦 Установка и запуск

### 1. Установка зависимостей
Для установки всех необходимых библиотек используйте файл `requirements.txt`:
```bash
pip install -r requirements.txt
```

### 2. Запуск исследования
Откройте Jupyter Notebook в среде выполнения:
```bash
jupyter notebook transformers.ipynb
```
Все ячейки тетрадки содержат воспроизводимый код с фиксированным зерном генерации случайных чисел (`set_seed(42)`).
